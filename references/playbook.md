# 招式库

按首屏拆解看到的实际瓶颈挑，别照单全抓。每一招都写了出处：「原文」指 Anthropic 那篇博客里 Claude 真做过的，「通用」指 Web 性能的常见做法。

## 首屏：让页面早点能用

| 招式 | 什么时候用 | 风险与护栏 | 出处 |
|---|---|---|---|
| 静态外壳：把能用的输入框直接写进 HTML，框架还在初始化时用户就能输入，框架挂载后接管 | 首屏卡在框架加载 | 交接时丢字、走样。护栏：交接瞬间持续打字，丢一个键或乱序就失败；多种视口尺寸下对齐误差 ≤1px；线上上报交接偏移 | 原文 |
| 重型库按需加载：导出图片、富文本粘贴、图表这类只在点了某个功能才用的库，用到时再加载 | 首屏关键路径上有「用不到」的库 | 所有入口都要改成先加载再调用；功能冒烟要覆盖每个入口 | 通用 |
| 第三方库同源托管或合并 | 首屏被外部 CDN 的下载拖住 | 锁定和线上相同的版本；部分地区访问公共 CDN 不稳定，同源托管顺带解决 | 通用 |
| `defer` / `async` / 推迟统计脚本 | 同步脚本阻塞解析 | 脚本之间有初始化顺序依赖时会坏，改完跑冒烟 | 通用 |
| `preconnect`、首图 `preload` 和 `fetchpriority="high"` | 关键资源来自别的域名，或首图来得晚 | 几乎无风险 | 通用 |
| 去掉重定向链 | 入口多一次 308 跳转 | 链接和 canonical 统一写最终地址 | 通用 |
| 预编译代码缓存（Electron 主进程的 V8 code cache） | 桌面端冷启动慢 | 版本升级后缓存失效要自动重建 | 原文 |

## 切换与交互

| 招式 | 什么时候用 | 风险与护栏 | 出处 |
|---|---|---|---|
| 切换页面时不卸载重建常驻组件（比如输入框） | 每次切换都重新挂载 | 状态串台 | 原文 |
| 鼠标悬停时预取目标页数据 | 点进去要等数据 | 流量增加 | 原文 |
| 砍掉重复渲染（原文侧边栏重渲染砍了90%） | 一次操作触发大量重渲染 | 数据不刷新 | 原文 |
| 状态订阅普查：数一下一次按键触发多少个 hook、多少个订阅（原文输入框打字路径上有6900个 hook、900个订阅） | 打字、拖动卡 | 拆订阅时漏更新 | 原文 |

## 长内容渲染

| 招式 | 什么时候用 | 风险与护栏 | 出处 |
|---|---|---|---|
| 只重算还在变化的部分，已经完成的块缓存起来 | 每来一点内容或每按一个键，就整篇重算 | 缓存失效条件写错，显示旧内容。护栏：黄金测试逐字节比对 | 原文 |
| 重活挪到 worker（原文把代码块分词挪了过去） | 主线程长任务多 | 数据序列化开销 | 原文 |
| 防抖：停顿一小段再刷新 | 实时预览 | 预览会晚一点更新，这是手感取舍，交给用户定 | 通用 |
| 按帧预算逐帧测（原文用 DevTools 的 begin-frame 做确定性 120Hz 步进，每帧 8.33ms） | 流式输出、滚动不跟手 | 测量台要能控制帧 | 原文 |

## 隐藏开销（数了才看得见）

- 遗留的 `location.reload()`：原文每天有50万次隐藏重载，加载指标都看不到
- 闲置标签页的重复写入：原文每分钟把同样的缓存快照往 IndexedDB 复制两次，全在主线程
- 贵的 CSS 选择器：原文一个 `:root:has()` 让每次 DOM 变更多花 24ms，数样式重算次数能发现
- 字符串编码：V8 里一段字符串只要有一个非 Latin-1 字符（破折号、弯引号、任何汉字），整段就按双字节存储，正则会走慢路径。原文的修法是高亮前把代码块复制成单字节字符串。中文内容天然满足这个条件，做中文产品要特别留意
- 布局抖动：CLS 总分正常不代表没抖。原文用 Layout Instability API 把每次偏移对应到有名字的区域和阶段，发现31%的页面加载在用户什么都没动时有东西在挪

## 浏览器自身的边缘情况

原文遇到过：Chrome 从地址栏预渲染页面时，按当前标签页（带页脚的新标签页）的高度布局，显示后再调整，首屏元素会往下掉约10像素。无头浏览器没有浏览器界面，测试台看不到这类问题，要靠真实用户的录屏和线上上报。
